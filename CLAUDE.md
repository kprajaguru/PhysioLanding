# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A single-page marketing/landing site for **PhysioApp** (a clinic-management SaaS for physiotherapists), built with **TanStack Start** (React 19 + file-based router + SSR via Nitro). The project is synced with [Lovable](https://lovable.dev) — see the notice at the top of `AGENTS.md`.

**Lovable sync constraint:** never force-push, rebase, amend, or squash commits that are already pushed to the connected branch — that rewrites history on Lovable's side and can lose the user's project history. Keep every pushed commit in a working state.

## Commands

Package manager is **bun** (`bun.lock` present; `bunfig.toml` sets a 24h supply-chain guard on new package versions — ask the user before adding an entry to `minimumReleaseAgeExcludes`).

```bash
bun run dev        # start dev server (vite dev)
bun run build      # production build (vite build)
bun run build:dev  # development-mode build
bun run preview    # preview a production build
bun run lint       # eslint .
bun run format     # prettier --write .
```

There is no test suite configured in this repo.

## Architecture

- **Routing**: TanStack Start file-based routing rooted at `src/routes/`. `src/routes/__root.tsx` is the only root layout/shell (head tags, fonts, global `<QueryClientProvider>`, 404/error boundaries) — do not create Next.js/Remix-style `src/pages/` or `app/layout.tsx`. See `src/routes/README.md` for the file-to-URL naming conventions (`$id` dynamic segments, `{-$category}` optional segments, `$` splats, `_layout.tsx` layouts). `src/routeTree.gen.ts` is auto-generated by the router plugin — never hand-edit it.
- **Entry points**: `src/router.tsx` creates the TanStack Router instance (wires up `QueryClient` into route context). `src/start.ts` registers a server-side `createMiddleware` that catches unhandled server errors and renders a fallback error page. `src/server.ts` is the Cloudflare/Nitro-style fetch handler; it wraps the generated `@tanstack/react-start/server-entry` and additionally normalizes a specific h3 failure mode (h3 swallows in-handler throws into a generic `{"unhandled":true,"message":"HTTPError"}` 500 JSON response), recovering the original error via `src/lib/error-capture.ts`'s out-of-band `error`/`unhandledrejection` listeners so it can still be logged and rendered with `src/lib/error-page.ts`.
- **Error reporting**: `src/lib/lovable-error-reporting.ts` forwards uncaught render errors to Lovable's in-browser event bus (`window.__lovableEvents.captureException`) from the root route's `errorComponent`; it's a no-op outside the Lovable preview iframe.
- **Page content**: The entire landing page is implemented as one large component tree in `src/routes/index.tsx` (Nav, Hero, FeatureHub, FeatureWheel, BuiltForEveryone carousel, Pricing, FAQ, FinalCTA, Footer) — sections are colocated in this file rather than split into separate component files. `src/components/FeatureMarquee.tsx` is a standalone marquee component with inline SVG illustration cards. `src/components/ui/*` is the shadcn/ui component library (New York style, configured in `components.json`; import via the `@/components/ui` alias — see `components.json` for all path aliases and regenerate/add components through the shadcn CLI rather than hand-rolling primitives).
- **Styling**: Tailwind CSS v4 (CSS-first config, no `tailwind.config.js`) — theme tokens live in `src/styles.css` under an `@theme inline` block mapping CSS custom properties (defined in `:root`/`.dark` using oklch) to Tailwind color utilities. Section-level one-off colors in `index.tsx` are currently hardcoded hex (`#14b8a6` teal, `#F97316` orange CTA, `#0F172A` slate text) rather than theme tokens — follow the existing pattern in a given section rather than mixing token and hex approaches within it.
- **Path alias**: `@/*` maps to `src/*` (defined in both `tsconfig.json` and enforced by `vite-tsconfig-paths`, injected automatically by `@lovable.dev/vite-tanstack-config`).
- **Vite config**: `vite.config.ts` wraps `@lovable.dev/vite-tanstack-config`, which already bundles TanStack devtools, `tanstackStart`, `viteReact`, `tailwindcss`, `tsConfigPaths`, `nitro` (Cloudflare target by default), env injection, and dedupe/sandbox plugins — do not re-add any of those plugins manually, it will break the build with duplicates. Only pass extra config through the `vite: { ... }` escape hatch if needed.
- **`.lovable/`**: `plan.md` and `project.json` are Lovable's own state tracking (current design direction, template revision) — informative context, not something to maintain by hand.
